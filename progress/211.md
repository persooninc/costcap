# #211 Hosted receipt retention

- New `src/hosted/retention.js` (pure) plus `GET/POST /v1/retention` (owner/admin session only; viewer and API key get 403; 7 to plan limit or null; audited `retention.change` before/after). `GET` returns `days`, `cutoff`, `eligible_count`.
- `purgeExpiredReceipts()` is returned by `createHostedServer`. `run.js` runs it 60 s after startup and then every 24 h. It deletes expired receipts and their settlements and writes one `receipts.purge` audit entry per org (`count`, `cutoff`). It never deletes receipts from the last 32 days, the current UTC month or the budget month, or unsettled unknown or pending-batch receipts.
- Ingest: receipts past the cutoff are acknowledged in `acceptedIds` but not stored, and the response reports `expired`.
- Dashboard: a Receipt retention card with a preview count. The trust page text and the README are updated.
- Postgres needs no migration: purged keys become `DELETE` rows (tested with a fake pool).
- Tests: `test/hosted-retention.test.js` (unit, roles, boundary, floor, isolation, ingest, audit, `/budget` regression, Postgres diff) and `e2e/retention.spec.js`.
