# #207 Budget-triggered model downgrade

- Landed on main in ca4535d: `wrap --downgrade FROM=TO[,FROM=TO] [--downgrade-at F]` (default 0.8). Past F of the first run/hour/day/month cap (local, `--policy` agent/team, enrolled fleet agent/team), only the JSON `model` is rewritten on openai/anthropic/openrouter/custom routes, before the allowlist, unknown-models, preflight, tag caps and cache key. Unsupported routes (Gemini path, Bedrock/Vertex, batches, multipart audio, Realtime, OpenRouter `models[]`) pass through with `downgrade: "unsupported_route"`. An unpriced TO exits 2 at start. The hard stop at 100% is unchanged.
- Records: receipt `model: TO, requested_model: FROM, downgrade: {scope, fraction}`, header `x-costcap-model-downgraded`, one `model_downgrade` ledger and stderr line per scope and period, `downgraded_calls` in the run summary and `costcap runs`. Fleet `downgrade: {at, map}` is validated, merged (local only adds or tightens) and editable on the dashboard agent card.
- Tests: `test/downgrade.test.js`, `test/proxy-downgrade.test.js`, `e2e/downgrade.spec.js`. Re-verified green on main 2026-11-16 (108/108 targeted).
