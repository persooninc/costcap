# 207: budget-triggered model downgrade (2026-11-16)

- `wrap --downgrade FROM=TO[,FROM=TO] --downgrade-at F` (default 0.8) and fleet policy `downgrade: {at, map}` (agent card, validated, 400 on invalid, cached offline). Past F of the first run/hour/day/month scope of any local, `--policy` agent/team or fleet agent/team cap, the proxy rewrites only the JSON `model` field before every check, so the allowlist, `--unknown-models refuse`, preflight, tag caps and the cache key use TO. The hard stop at 100% is unchanged.
- Receipt `requested_model` + `downgrade: {scope, fraction}`, header `x-costcap-model-downgraded`, one `model_downgrade` ledger/stderr line per source/scope/period, `downgraded=N` in the rollup and `costcap runs`. Unsupported routes pass through with `downgrade: "unsupported_route"`.
- Tests: `test/downgrade.test.js`, `test/proxy-downgrade.test.js`, `test/hosted-downgrade.test.js`, `e2e/downgrade.spec.js`.
